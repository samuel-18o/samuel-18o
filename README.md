## 🧠 About me

I'm a backend developer focused on **AI integration and process automation.**
I think in workflows first — understanding how a solution will actually be used
before deciding how it will be built.

I've worked on projects across **cybersecurity, freelancer productivity and accessible workforce training**, always with the same approach:

> **Connect the right tools. Design the right flow. Solve the right problem.**

<img src="https://raw.githubusercontent.com/andreasbm/readme/master/assets/lines/colored.png" width="100%"/>

## ⚙️ What I build & Why it matters

Most AI implementations stop at the chatbot.
I start there and ask: **what should this actually trigger?**

```text
A user asks a question
→ The AI understands the intent
→ The right tool gets called
→ A real process gets executed
→ The user gets a result, not just an answer
```

> *That's the difference between AI as a feature and AI as infrastructure.*

<br/>

<details>
<summary>💡 How I approach every project</summary>

<br/>

**1. Problem before stack**
I map the workflow and the user journey before choosing any technology.
If the tool doesn't make the experience faster or clearer, it doesn't belong.

**2. Fallback by design**
Systems fail. I build with that in mind — whether it's a cloud/local model
fallback like OpenAI → Ollama, or a graceful error in an n8n workflow.

**3. Real users, not developers**
The end user of what I build is rarely another developer.
I optimize for clarity, speed and retention — not just for functionality.

</details>
